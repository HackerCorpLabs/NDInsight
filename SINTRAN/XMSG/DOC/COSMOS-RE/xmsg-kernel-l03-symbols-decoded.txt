# APPENDIX, added 2026-08-18: the XT-block (XMSG task descriptor), L03 versus
# version J, and the field comments J gives for the offsets that did not move.
#
# Source for the J side: SINTRAN/NPL-SOURCE-2/NPL-CLEAN/10-XMSG-SYSTABS.NPL,
# the "DESCRIPTION OF AN XT-BLOCK" DISP block. That listing is CLEAN - it is
# not OCR - so these comments are the authoritative wording, not a guess.
# Source for the L03 side: the value index above (grep for "XT").
#
# Offsets are OCTAL, as in both sources.
#
# Off  J field   J's own comment                              L03 field(s)  Delta
# ---  --------  -------------------------------------------  ------------  -----
# 0    XTCHN     chain for free / waiting for resources       XTCHN         same
# 1    XTSTA     status word                                  XTSTA         same
# 2    XTRTA     RT-address, or 0 if driver                   XTRTA         same
# 3    XTPRT     port chain header (first in the queue)       XTPRT         same
# 4    XTMEM     number of bytes of memory in use             XTMEM         same
# 5    XTMMX     max amount of memory allowed                 XTRSE         CHANGED
# 6    XTCMS     task current message                        XTCMS         same
# 7    XTSTS     bit 17 paging status; bits 0-4 int level     XTSTS         same
# 10   XTPRG     register save area starts here               XTPRG/XTDXR   same
# 11   XTXRG                                                  XTXRG/XTZRG   same
# 12   XTTRG                                                  XTTRG/XTFRG   same
# 13   XTARG                                                  XTARG/XTMRG   same
# 14   XTDRG                                                  XTDRG         same
# 15   XTLRG                                                  XTLRG         same
# 16   XTSRG                                                  XTSRG         same
# 17   XTBRG     ... register save area ends here             XTBRG         same
# 20   XTAPR     saved ACTPRI while on level 1 (YSTL1)        XTAPR/XTDTR   same
# 21   XTTAP     ACTPRI to set up transfer windows            XTTAP/XTTDF   same
# 22   XTUBF     user buffer address                          XTUBF         same
# 23   XTSBK     system buffer BANK; BIT 15 => user->system   XTSBK/XTSAD   same
# 24   XTSBF     system buffer address                        XTSBF         same
# 25   XTCNT     transfer count in BYTES                      XTCNT         same
# 26   XTTCN     dynamic counter used by XTRAN                XTTCN         same
# 27   XTHOM     return address from XTRAN (also XDHAN)       XTHOM         same
# 30   XTASG     actual segments 1 and 2                      XTASG/XTDAR   same
# 31   XTRSG     re-entrant segment                           XTUSG/XXTAS   RENAMED
# 32   XTBM0     bit map                                      XTACH         CHANGED
# 33   XTBM1                                                  XTAMS         CHANGED
# 34   XTBM2                                                  XTUAC         CHANGED
# 35   XTBM3     ... bit map ends; J's block ends here        XTUMS         CHANGED
# 36   -         -                                            XTMMH/XTMMX   MOVED HERE
# 37   -         -                                            XTMML         MOVED HERE
# 40+  -         -                                            XTFUN 40, XTCON 41, XTDLR 50,
#                                                             XTDSR 60, XTDBR 70, XTFRE 115,
#                                                             XTUSE 116, XTMAX 117, XTLIM 120
#                                                                           NEW IN L
#
# WHAT THIS MEANS IN PRACTICE - the reason the appendix exists:
#
#   NEVER apply a J offset 5, 31, or 32-35 to an L kernel. The memory allowance
#   moved from a single word at offset 5 to a wider quantity at 36-37 (XTMMX is
#   the collective name over XTMMH/XTMML), and the four bit-map words at 32-35
#   were replaced outright.
#
#   Offsets 0-4 and 6-30 ARE stable, so the J comments above can safely be read
#   as documentation for the L03 names at those offsets - including the one that
#   is easy to get wrong: BIT 15 OF XTSBK IS THE TRANSFER DIRECTION (set means
#   user-to-system), and XTCNT counts BYTES, not words.
#
#   None of this is modelled in the C# library on purpose. The XT block is kernel
#   internals; our API models ports, buffers and quotas instead. See
#   DOC/COSMOS-RE/XMSG-ENUM-STRUCT-AUDIT-2026-08-10.md ("do NOT build them
#   speculatively"). What changed on 2026-08-18 is only that the field meanings
#   are now sourced rather than guessed.
