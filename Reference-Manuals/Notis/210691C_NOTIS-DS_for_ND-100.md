**Title:** NOTIS-DS revision C02.

---

## ERRORS CORRECTED IN REVISION C02

The following error corrections and improvements are done:

### The servers

- Less output of irrelevant error messages on console.
- Improvement in handling of communication related error situations.
- User running out of storage blocks/objects is reported on console.
- Corrected error in using " " and "-" in otherwise equal names.
- Corrected error permitting access from system not in access-table.
- Corrected error causing the text of documents copied/moved/sent (using NOTIS-ID) not to be deleted when document is deleted.

**NOTE:** In order for the last correction to work, it is necessary to run the command `CORRECT-REFERENCES` in the `DS-SUPPORT` program before starting the servers. The installation procedure deals with this.

### The Service program

- Completion code is added.
- Output from the Service program stops on full page.
- The available commands for ordinary users is not as limited as before.

### 2.1 Changed commands

The list function in the document manager also includes a search on the keywords of a document.

The BACKUP-SYSTEM can now be run from a MODE-file.

### 2.2 Deleted commands

The Administration commands in the document manager are moved to the SERVICE-program.

### 2.3 New commands

This version of NOTIS-DS includes a SERVICE-program, and it contains the former DS-DBCOPY, DS-VERIFY, DS-DS-STOP and DS-BS-STOP programs, as well as other supervisor functions.

## 3 BEFORE INSTALLATION

Before you start, note the following points:

1) You should read the NOTIS-DS Supervisor Guide before starting.

2) NOTIS-DS consists of two parts, the document server and the document manager. The document server is an RT program running the storage system (keeping all documents in the document database). The document manager is a utility program for creating, listing, etc. of users, drawers, folders and documents.

- Further, a system for personal backup is supplied. It consists of an interactive (background) part and an RT program.

- The DS-SERVICE program is used for taking backup of the complete database and for regenerating a possibly inconsistent database, as well as for other supervisor tasks.

- In a COSMOS network, the document server (i.e. the database) may be shared by many computers, and may be installed on one centrally located computer. The document manager must be installed on all computers.

### 3) Installation Program Assumptions

The installation program assumes the following default user areas to be used:

| System Component | Minimum Pages             |
|------------------|---------------------------|
| SYSTEM           | minimum 186 pages         |
| NOTIS            | minimum 732 pages (files) |
| NOTIS-DS         | minimum 70 pages (database)|

You may choose user areas other than NOTIS and NOTIS-DS during the installation procedures. The NOTIS user area is used to hold all files, while the NOTIS-DS user area holds the database containing all documents and their information. This user area needs 70 pages plus 1.1 pages for each document, folder, drawer and user, in addition to the space occupied by the document contents.

Before you start, it is a good idea to make sure that all necessary users exist and have enough pages, although you will be allowed to allocate more space during the installation.

If **XMSG** is running, you should give the following command before you start the installation:

```
@(utility user>)XMSG-COMMAND
DEFINE-REMOTE-NAME,*DSSYSTEM <sysno>
EXIT
```

`<sysno>` is the system number of the system running the document server. (needed even if the server is to be installed on the local computer). Use the `SINTRAN` command `LIST-TITLE` on the computer to hold the database if you do not know the number.

*NOTE*: These statements should be included in your XMSG-START:MODE file, as you will not be able to use NOTIS-DS before they are executed.

If the A-version of the NOTIS-DS system, including a database, was previously installed on your system, you have to install the B-version before installing the C-version, in order to convert the database to the correct format.

If the `UE-ERMSG-XX-<Crev>:ERR` (`xx` = language, `<rev>` = current revision) file on user area SYSTEM is in use by a program and if this file is older than the one on the diskette, then the installation procedure will not be able to replace it and will install the new `ERR` file with the file type `NEW`.

## 5 After Installation

1. Include the following statement in your HENT-MODE file:

    ```
    @MODE (<Utility user>)DS-LOAD-<lang>-C:MODE,,
    ```

    ```
    @(<Utility user>)DS-SERVICE
    ```

**Program:** Inst. procedure.  
**Title:** Error in installation procedure for NOTIS-DS version C02.  
This applies only to those upgrading from C01 to C02.

---

Follow the installation procedure as it is described in the PD- sheets until you reach the point where the installation program asks the following question:

Do you want to "correct references" now? (Def: Yes)

Due to an error in the installation procedure, it does not matter what you answer, as at this point the files do not have the correct access. The MODE file will therefore not be run.

To correct this error do the following when the installation procedure is finished:

- set public access on the file:
  (DOMAIN/FIILS USER)DS-CORR-REF:MODE

- enter the user where the database is
  (normally NOTIS-DS)

- type the command:
  MODE (DOMAIN/FIILS USER)DS-CORR-REF:MODE  
  "DS-CORR-REF:LIST"

- look in the file DS-CORR-REF:LIST for any error messages. If the file does not contain any error messages everything is OK.

You can now go back to user SYSTEM and start the servers.
