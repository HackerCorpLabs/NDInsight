## Installation Procedure

COSMOS Basic Module consists of 4 parts:

- CONNECT-TO, which performs login to other machines
- FILE-TRANSFER, which allows for transfer of files to other computers in the network
- COSMOS SPOOLING, which performs remote spooling
- FILE ACCESS, consisting of the FILE USER and FILE SERVER parts, which allow for remote file access

The installation program gives you the opportunity to install the whole or only parts of the COSMOS Basic Module.

**Please read through this installation procedure before performing the installation.**

- Log in as user area SYSTEM.
- Delete the old file IN-COS-BAS:PROG, if it is present.
- Insert the diskette 210374G<rev>-XX-01D in the floppy drive.
- Type the command:

  ```
  @ENTER-DIRECTORY 210374G FLOPPY-DISC-1 <unit>
  ```

- Copy the installation program from the floppy:

  ```
  @COPY-FILE
  DESTINATION FILE: "IN-COS-BAS-G<rev>:PROG"
  SOURCE FILE: (210374G:FLOPPY-USER)IN-COS-BAS-G:PROG
  ```

## COSMOS Basic Module 210374G

- This installation program copies the files to a single user area of your choice (default is COSMOS-BASIC). For easy maintenance, we suggest that you create user area COSMOS-BASIC just for the COSMOS Basic Module.  
  User area COSMOS-BASIC should have 500 pages of storage space.

- The program will prompt for information to ensure a successful installation.  
  All answers to the installation program must be terminated by a carriage return (CR).

- Please note that if you choose to copy only parts of the product, you will have to edit the files COSMOS-HENT-G:MODE and COSMOS-START-G:MODE to exclude those parts you do not want.

- Start the installation program by typing:

  ```
  @IN-COS-BAS-G<rev>
  ```

- After finishing this installation program, delete the file IN-COS-BAS-G<rev>:PROG and follow the description below to get the system running. The description tells you which modifications you must make to the files run after a cold start (usually called HENT-MODE:MODE) and after a warm start (usually called LOAD-MODE:BATC).

- In the following, `<user name>` must correspond to the user name you copied the files to during the installation.

- Now take a look at the two mode files (`<user name>`)COS-HENT-G:MODE and (`<user name>`)COS-START-G:MODE. You need to delete the lines that concern the services you are not using.

In the HENT-MODE file, insert the line:

```
@MODE (<user name>)COS-HENT-G:MODE,,
```

anywhere after the command INITIALIZE-BACKGROUND-PROGRAMS is executed.

Suggestion for HENT-MODE:MODE:

```
:
@INITIALIZE-BACKGROUND-PROGRAMS
:
@MODE (<user name>)COS-HENT-G:MODE,,
:
```

Also, delete any lines that have to do with previous version(s) of COSMOS Basic Module.

## COSMOS Spooling

It is a prerequisite that SINTRAN III is configured with COSMOS Spooling.

Take a look at the mode file (<user name>)COS-DEF-PRIN-G:MODE, and edit the file according to your network/printer configuration.

If COS-DEF-PRIN:MODE exists, then you can copy it into COS-DEF-PRIN-G:MODE without changing anything, except perhaps the <user name> in the file.

## File-Transfer

The content of the file (<user name>)COS-XFTRA-G:MODE may be modified to get another timeout value, another batch processor for remote batch, and/or another priority for the RT part of File-Transfer. You can, of course, use the default values as they are.

- Now make sure that no one is logged in on the system.


  ```
  @SET-AVAILABLE ↵
  ```
  
  and broadcast a 'system available' message.

### Modifications

#### Improved performance

The FILE TRANSFER service now works significantly faster when transferring files containing "holes".

#### Improved security

If a user repeatedly tries to access a file on a remote system by specifying an erroneous password, this is now reported.

The attempts are reported to the error device (using the SINTRAN Watchdog) on the target system every 20th attempt and the user will be denied further access to the remote file server (the error message "Remote File Server is not Available" is returned).

## New functions

- The COSMOS File Server now supports the new functions offered by the monitor calls MON IOPEN (MON 351) and MON FSMTY (MON 327) function 14₈.
- The COSMOS Connect-To is also changed somewhat when running User Environment version D. Connecting to a system in the same UE local domain, also means logging into that system as the same User Environment user.  
  This is called "Automatic UE local domain login".

## Errors corrected

In the FILE USER service, the following two error situations are corrected:

- Attempting remote file access when XMSG is not running.  
  This previously led to overwriting parts of SINTRAN itself.
  
- Closing a remote spooling file when the spooling queue on the remote system is full.  
  Previously, there was no error message (and no print-out), and the tidying up of this situation was not complete.  
  The error message "Remote Spooling Queue is Full" is now shown, and the File Access Server will now do a complete clean-up.

## Errors known, but not corrected

The error message "No Answer from Remote System" is sometimes given when one of the two messages "Attempt to Open Too Many Connections" or "No Access to Remote System" is the correct one.
